# 실무 운영 전환 시 할 일

지금 구성은 **예산 $200 안에서 데모를 위한 구성**입니다. 실제 회사에서 운영한다면 아래를 바꿔야 합니다. 현재 동작은 [architecture.md](architecture.md)·[aws.md](aws.md), 배포 명령은 [deploy/README.md](../deploy/README.md)에 있습니다.

비용은 서울 리전 공시가 기준 대략값입니다(2026-10-30 기준, 사용량에 따라 달라짐). 이 문서의 항목은 아직 하나도 적용하지 않았습니다.

## 현재 상태 요약

| 항목 | 지금 | 실무 기준 |
|---|---|---|
| 노드 위치 | 퍼블릭 서브넷, 노드에 퍼블릭 IP (NAT 없음) | 프라이빗 서브넷 |
| ALB 접근 | 인터넷 어디서나 HTTP로 직접 접근 가능 | CloudFront(또는 WAF)만 통과 |
| CloudFront → ALB | HTTP (`origin_protocol_policy = "http-only"`) | HTTPS (자체 도메인 + ACM 인증서) |
| EKS API 엔드포인트 | 퍼블릭 접근 허용(제한 없음) | 허용 IP 제한 또는 프라이빗 전용 |
| DynamoDB | 시점 복구(PITR)·삭제 보호 없음 | 둘 다 켬 |
| Cognito | 삭제 보호 꺼짐, MFA 없음 | 삭제 보호 켬, 검수·관리자 MFA |
| 카드번호 | 찍힌 그대로 저장(서비스 결정) | 마스킹 또는 필드 암호화 검토 |
| 중복 분석 | SQS 재전달 시 같은 영수증을 다시 분석할 수 있음 | 멱등 처리 |
| 모니터링 | 비용 메일·예산 알림만 | 로그 수집·지표·알람 |
| 가용성 | web·preprocess·ocr-worker 1개, PDB 없음 | 2개 이상, PDB, AZ 분산 |
| 환경 | 개발·데모가 같은 AWS 리소스 공유 | 개발·운영 분리 |

이미 되어 있는 것: S3·SQS 서버 측 암호화, ECR 푸시 시 이미지 스캔, Terraform 상태 S3 백엔드(버전 관리·암호화), Pod별 IAM 역할(Pod Identity), GitHub OIDC 배포(키 없음), 배포 매니페스트의 개발자 로그인 차단 검사.

## 1. 네트워크 (우선순위 높음)

1. **프라이빗 서브넷으로 이동**: AZ별 프라이빗 서브넷을 만들고 노드 그룹을 옮깁니다. 퍼블릭 서브넷에는 ALB(와 NAT)만 둡니다. 노드 그룹의 서브넷은 바꿀 수 없어 **새 노드 그룹을 만들고 옮긴 뒤 기존 것을 지웁니다**(데모 직전에는 하지 않음).
2. **밖으로 나가는 길** — 둘 중 하나 또는 조합:
   - **NAT 게이트웨이**: 시간당 약 $0.059 → **AZ당 월 약 $43** + 처리 데이터 GB당 약 $0.059. 가용성을 위해 AZ마다 하나씩 두면 그만큼 곱해집니다.
   - **VPC 엔드포인트**: S3·DynamoDB는 게이트웨이형이라 **무료** — NAT를 쓰더라도 이 둘은 꼭 붙여 데이터 처리 비용을 줄입니다. ECR(api·dkr)·SQS·STS·Bedrock Runtime·CloudWatch Logs·EKS Auth는 인터페이스형으로 **엔드포인트당 AZ당 시간당 약 $0.013**(월 약 $9.5) — 6~7개 × AZ 2개면 NAT보다 비쌀 수 있습니다.
   - 권장 조합: NAT 1~2개 + S3·DynamoDB 게이트웨이 엔드포인트.
3. **EKS API 엔드포인트 제한**: `public_access_cidrs`를 사무실·VPN IP로 제한하거나 프라이빗 전용으로. GitHub Actions 배포는 러너 IP가 바뀌므로 자체 러너(VPC 안) 또는 다른 배포 방식이 필요합니다.

## 2. 입구 보안

1. **자체 도메인 + ACM 인증서**: Route 53 도메인(연 약 $13~) + ACM(무료). CloudFront와 ALB 모두 HTTPS로, CloudFront → ALB 구간도 `https-only`.
2. **ALB를 CloudFront만 받게**: ALB 보안 그룹 인바운드를 CloudFront 관리형 접두사 목록(`com.amazonaws.global.cloudfront.origin-facing`)으로 제한하고, CloudFront가 붙이는 비밀 헤더가 없는 요청은 ALB 규칙에서 거절합니다.
3. **AWS WAF**: CloudFront에 관리형 규칙(공통·알려진 악성 입력) + IP별 요청 수 제한. 웹 ACL 월 $5 + 규칙당 월 $1 + 요청 100만 건당 $0.60.

## 3. 데이터 보호

1. **DynamoDB**: 시점 복구(PITR, 35일) + 삭제 보호. PITR은 저장 GB당 월 약 $0.2(지금 데이터 규모면 거의 0).
2. **Cognito**: 삭제 보호 `ACTIVE`, 검수 담당자·관리자 MFA 필수, 비밀번호 정책 점검.
3. **S3 영수증 버킷**: 고객 관리 KMS 키(SSE-KMS, 키당 월 $1 + 요청 비용)로 바꾸면 접근 기록·권한을 따로 관리할 수 있습니다. 퍼블릭 액세스 차단 유지.
4. **카드번호**: 지금은 서비스 결정으로 찍힌 그대로 저장합니다. 실무에서는 카드 정보 보호 기준(PCI DSS)상 마스킹(앞 6·뒤 4자리) 또는 필드 단위 암호화가 필요합니다. 기획 결정 변경이므로 `contract.md`·검수 화면·CSV를 함께 바꿉니다.
5. **로그의 개인정보**: 애플리케이션 로그에 카드번호·이름이 남지 않는지 점검합니다.

## 4. 안정성

1. **중복 분석 막기(멱등)**: ocr-worker가 저장할 때 DynamoDB 조건부 쓰기(분석 상태·버전 확인)로 같은 결과를 두 번 쓰지 않게 하고, 오래 걸리는 분석은 SQS 가시성 제한 시간(지금 180초)을 연장합니다. ([worker.md](worker.md)의 "실패·재시도와 중복 처리")
2. **Pod 2개 이상 + PDB**: web·preprocess·ocr-worker도 최소 2개, 서비스마다 PodDisruptionBudget, `topologySpreadConstraints`로 AZ에 나눠 배치. 노드도 AZ별 최소 1대.
3. **노드 종류**: 기본은 온디맨드, 워커처럼 끊겨도 되는 작업은 Spot 노드 그룹(최대 약 70% 저렴)으로 분리 검토.
4. **ECR 태그 고정**: `image_tag_mutability = "IMMUTABLE"` — 같은 태그로 다른 이미지를 덮어쓰지 못하게 합니다.

## 5. 모니터링·알람

1. **로그 수집**: CloudWatch Container Insights(또는 Fluent Bit)로 Pod 로그·지표 수집, EKS 컨트롤 플레인 로그(감사·인증) 켜기. 로그 보관 기간을 정합니다(예: 30일). 수집 GB당 약 $0.76이 들어 로그 양을 먼저 줄입니다.
2. **알람**(CloudWatch → 이메일·Slack):
   - ALB 5xx 비율, 응답 시간
   - SQS 가장 오래된 메시지 나이(분석 지연), DLQ 메시지 수 > 0
   - Bedrock 호출 오류·제한(throttling)
   - 노드·Pod 재시작, CPU·메모리
3. **비용**: 지금처럼 Budgets 알림 유지, 서비스별 비용 태그 정리.

## 6. 환경·배포

1. **개발·운영 분리**: 지금은 로컬 개발과 EKS가 같은 테이블·버킷·큐·Cognito를 씁니다. 운영은 별도 리소스(가능하면 별도 AWS 계정)로 나누고, Terraform은 환경별 변수·상태로 관리합니다.
2. **운영 배포 승인**: GitHub `demo` 환경처럼 운영 환경을 만들고 **필수 승인자**를 지정해 사람 승인 후 배포. 스테이징에서 먼저 확인합니다.
3. **롤백 절차**: 이전 커밋 태그로 `kubectl rollout undo` 또는 해당 태그로 재배포하는 절차를 문서화합니다.
4. **로컬 워커 분리**: 운영 큐는 EKS 워커만 소비하고, 로컬 워커는 개발 큐에만 연결합니다.

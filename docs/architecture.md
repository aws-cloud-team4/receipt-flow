# receiptflow 전체 구조 (먼저 읽는 문서)

직원이 업무용 **카드 영수증**을 찍어 올리면 AI가 증빙 정보를 읽고, AI 어시스턴트가 결과 확인 → 지출 목적·분류 → 최종 확인까지 함께 진행합니다.
**재무회계부 검수 담당자**가 먼저 제출된 순서대로 승인하거나 보완을 요청하고, **관리자**가 계정과 증빙을 관리합니다.
AWS 클라우드 AI 부트캠프 4인 팀 프로젝트이고, 발표일은 2026-11-14, AWS 예산은 $200입니다.

## 1. 시스템 한 장 그림

```
                         ┌──────────────── 브라우저 (React, web/) ────────────────┐
                         │ 직원: 촬영·업로드·AI 대화·제출   검수: 목록·상세·승인   관리자: 계정·증빙 │
                         └──────┬───────────────┬──────────────────┬──────────────┘
          로그인(Cognito 직접)  │   /api        │ /chat (SSE)      │ /preprocess        사진 PUT(미리 서명된 URL)
                                ▼               ▼                  ▼                       │
                         ┌────────────┐  ┌─────────────┐  ┌──────────────────┐           ▼
                         │api-service │  │chat-service │  │preprocess-service│     S3 raw/{id}.jpg (원본)
                         │증빙·검수·관리│  │AI 어시스턴트 │  │테두리 찾기·자르기  │────▶ S3 incoming/{id}.jpg (보정본)
                         └─────┬──────┘  └──────┬──────┘  └────────┬─────────┘            │ S3 이벤트
                               │                │ Bedrock(Haiku)   │                       ▼
                               ▼                ▼                  ▼                  SQS 분석 큐 (+DLQ)
                         ┌──────────────────── DynamoDB 단일 테이블 ─────────────┐          │
                         │ 증빙 본문 · 처리 이력 · 대화 · 삭제 기록 · 사번 카운터 │◀── ocr-worker ── Bedrock(Sonnet)
                         └───────────────────────────────────────────────────────┘   (사진 → 필드 추출)
```

- **로컬 개발**: 서비스 4개를 PC에서 띄우고(포트 8000–8002 + 워커), 웹 개발 서버(5173)가 경로별로 넘겨줍니다. **AWS 리소스(S3·SQS·DynamoDB·Cognito·Bedrock)는 팀이 하나를 같이 씁니다.**
- **배포(EKS)**: 같은 이미지 5개(서비스 4 + 웹)를 EKS에 올리고, ALB가 같은 경로로 나누며, CloudFront가 HTTPS 주소를 줍니다. 발표·리허설 때만 켜고 같은 날 지웁니다.
- 서비스끼리는 직접 호출하지 않습니다. **DynamoDB와 S3·SQS를 통해서만** 이어집니다 (서비스 하나를 고쳐도 다른 서비스가 깨지지 않게).

## 2. 영수증 한 장이 지나가는 길

1. **만들기** — 웹 `POST /api/receipts` → api-service가 `draft` 증빙과 원본 업로드 URL(`raw/{id}.jpg`)을 줍니다. 작성자 프로필(사번·부서·직급)을 증빙에 복사해 둡니다.
2. **사진 올리기** — 브라우저가 사진을 긴 변 최대 3200px JPEG로 줄여 S3 `raw/`에 직접 PUT (작은 글씨를 살리려고 보정본 2400px보다 크게 둠).
3. **테두리 확인** — `POST /preprocess/.../detect`가 네 모서리와 흐림 점수를 돌려주고, 화면(`CornerEditor`)에서 사람이 끌어 맞춘 뒤 `apply` → 서버가 원근 보정해 `incoming/{id}.jpg` 저장.
4. **분석 시작** — `POST /api/receipts/{id}/uploaded` → `analysis_status=queued`. `incoming/` 저장이 S3 이벤트 → SQS로 갑니다. 화면은 분석이 끝날 때까지 1.5초마다 증빙을 다시 불러옵니다.
5. **추출** — ocr-worker가 큐에서 꺼내 Bedrock(Sonnet 5.5)에 사진을 보내 **도구 호출로 JSON을 강제**해 받습니다. 정규화·검산·중복 점검 후 `fields`, `needs_check`, `ai_filled`, `checks` 저장, `analysis_status=done`. 추출 구간의 AWS 오류는 수신 횟수 기준 최대 3회 시도 후 `failed`로 저장하고 메시지를 삭제합니다. 오류별 즉시 실패·재시도·DLQ 동작은 [워커 실패 처리](worker.md#실패재시도와-중복-처리)를 따릅니다.
6. **AI 어시스턴트** — 웹이 분석 완료를 보면 `POST /chat/.../turn {event: "analysis_done"}`. 결과 카드 → [맞아요]/[직접 수정] → "어떤 일로 쓰신 비용인가요?" + 목적·분류 추천 버튼 → 분류 확인 → `check_submission` → **최종 확인 카드**. 답은 SSE로 흘러나옵니다.
7. **제출** — 사람이 [제출하기] → `POST /api/receipts/{id}/submit` (필수 칸·오류 검사) → `review_status=submitted`. **AI는 제출하지 않습니다.**
8. **검수** — 검수 담당자가 `/review`(먼저 제출된 순, "주의" 탭)에서 열고, 서버가 뽑은 **검토 포인트**를 보며 승인 또는 보완 요청(사유 + 다시 볼 칸). 건너뛰기는 맨 뒤로.
9. **보완 → 다시 제출** — 직원이 보완 요청된 증빙을 열면 AI가 사유와 고칠 칸을 안내하고, 고친 뒤 같은 최종 확인을 거쳐 다시 제출.
10. **내보내기** — 검수 담당자가 월별 CSV를 받습니다. 사진은 S3에서 90일 뒤 자동 삭제.

상태: `analysis_status` waiting → queued → processing → done|failed, `review_status` draft → submitted → approved | changes_requested → submitted. 규칙은 [contract.md](contract.md#상태).

## 3. 역할과 화면

| 역할 | Cognito 그룹 | 첫 화면 | 할 수 있는 일 |
|---|---|---|---|
| 직원 | `employee` | 홈(요약 줄·할 일·최근·지출 위젯) | 영수증 올리기, AI와 대화, 직접 수정, 제출, 보완 후 재제출, 작성 중 삭제, 내 증빙 목록(탭·분류·검색) |
| 검수 담당자 (재무회계부만) | `reviewer` | 홈(요약 줄·검토 대기열·최근·이번 달 승인) | 검수 목록(제출·주의·보완 요청·승인 탭, 부서·분류·검색), 상세에서 승인·보완 요청·건너뛰기, 월별 CSV |
| 관리자 (부서 없음) | `admin` | 계정 관리 | 계정 만들기·수정·임시 비밀번호·중지·삭제, 증빙 전체 보기·영구 삭제·삭제 기록. **작성·검수 화면 없음** |

모든 역할: 내 프로필(본인 비밀번호 변경), 로고 아래 막대(☰ 메뉴 · 현재 위치 · ⓘ 도움말), 왼쪽 메뉴(역할별 탭 바로가기). 자세히는 [ui.md](ui.md).

## 5. 기술 선택 요약

| 영역 | 선택 | 이유 |
|---|---|---|
| 웹 | React 18, React Router 6, Vite, 순수 CSS(변수) | 가볍고 빠름. 화면은 AWS 콘솔 느낌 |
| 백엔드 | FastAPI 4개 서비스 + 공통 패키지 (uv 워크스페이스) | 영역별 담당 분리, 서비스 하나씩 배포·확장 |
| 로그인 | Cognito 사용자 풀 (브라우저에서 직접 `USER_PASSWORD_AUTH`), ID 토큰을 서버가 JWKS로 검증 | 서버에 비밀번호가 오지 않음 |
| 데이터 | DynamoDB 단일 테이블 + GSI 2개 | 증빙·이력·대화를 한 키로, 서버리스 비용 |
| 파일 | S3 (`raw/` 원본, `incoming/` 보정본), 미리 서명된 URL | 서버를 거치지 않는 업로드 |
| 비동기 | S3 이벤트 → SQS(+DLQ) → ocr-worker | 분석이 느려도 화면이 막히지 않음, 재시도 |
| AI | Bedrock: 추출 Sonnet 5.5, 어시스턴트 Haiku 5.5 (global 추론 프로필) | 정확도·속도·비용 비교로 결정 ([model-eval.md](model-eval.md)) |
| 배포 | EKS(관리형 노드 그룹 t3.medium) + ALB + CloudFront, Pod Identity, Helm, kustomize | 기획서 아키텍처, 키 없이 권한 |
| IaC·CI | Terraform(상태 S3), GitHub Actions | 콘솔 수작업 금지 |

## 6. 현재 구현 상태

### 기획서 우선순위 기준 요약

| | 기능 | 상태 |
|---|---|---|
| Must | 로그인·역할 | ✅ Cognito, 직원/검수 담당자/관리자, 관리자의 계정·증빙 관리 |
| Must | 촬영·업로드 | ✅ 모바일 촬영·파일·재업로드, 서버가 테두리를 찾고 사용자가 확인·수정 → 원근 보정, 흐림 경고, 원본 보관(검수자 원본 보기) |
| Must | AI 추출 | ✅ Bedrock 도구 호출로 JSON 강제, 확인 필요 표시, 금액 검산 |
| Must | 챗봇 보완 | ✅ 분석이 끝나면 결과 확인부터 시작, 목적·분류 추천 버튼, 자유 답변 구조화, 최종 확인 카드, SSE |
| Must | 확인·수정·제출 | ✅ 사진 옆 수정, 필수 항목·검산 오류 시 제출 차단 |
| Must | 검수·상태 관리 | ✅ 승인 / 보완 요청(검토 포인트·칸에서 담기, 사유 선택) / 재제출, 처리 이력 |
| Must | 처리 현황 | ✅ 직원 내역, 담당자 상태별 목록 |
| Should | 지출 기준 점검 | 🟡 심야·주말·중복 경고 (기관별 설정은 미구현) |
| Should | 알림·내보내기 | 🟡 월별 CSV ✅, 알림은 범위 밖(하지 않음) |
| Should | 사진 위 결과 표시 | ⬜ 범위 밖 |
| Could | Athena 분석 | ⬜ |

처리 단계별 시각(`timings`)과 토큰 사용량(`model_usage`)은 증빙마다 저장됩니다.

### 최신 검증 범위

자동 검증(**2026-10-23**): 백엔드 테스트 **65개**, 웹 회귀 테스트 **11개**, ruff·웹 빌드 통과. 권한 우회 차단, 보완 안내·재제출, 검토 포인트의 `code`·`fields`, 시드 증빙을 모델에 보내지 않는 워커, 보완 요청 항목 합치기·한도 검사를 포함합니다. 보완 요청 작성 화면은 공용 개발 데이터로 383px 폭에서 담기·빼기·사진 경고·미리 보기까지 확인했고(보내기 제외), 1280px 폭은 요소가 패널 밖으로 나가지 않는지만 측정했습니다. 배포 검증(**2026-10-18**): Terraform 형식·설정 검증, 실제 EKS의 HTTPS·Pod Identity·AI 분석·노드 **2→3→2**·OCR 워커 **1→5→1** 확인. 실제 Cognito 사용자로 휴대폰 촬영부터 사람의 제출·승인까지 이어지는 전체 흐름은 미검증입니다.

## 7. 남은 일 (우선순위)

0. **사용자 전체 흐름 검증**: 실제 Cognito 직원·검수 계정으로 휴대폰 촬영 → AI → 사람이 제출 → 사람이 승인하는 전체 흐름은 미검증입니다. 발표 전 확인해야 합니다.

1. **팀 저장소 마무리**: 저장소는 [aws-cloud-team4/receipt-flow](https://github.com/aws-cloud-team4/receipt-flow)(공개, 이력 없이 시작)로 옮겼고 `main` 보호·squash 머지·CODEOWNERS가 켜져 있습니다. 남은 것: IAM 관리자가 `admin` 스택에 `-var github_repo=aws-cloud-team4/receipt-flow`로 apply → 출력 `github_deploy_role_arn`을 저장소 Secret `AWS_DEPLOY_ROLE_ARN`에 등록(자동 배포), 팀원 메일을 비용 보고에 추가, `state` 스택 상태 파일과 `ops/terraform.tfvars`(받는 메일)는 지금 IAM 관리자 PC 한 곳에만 있으므로 백업·공유 위치 정하기
2. **AI 품질**: 대화 평가 세트(시나리오 자동 실행), 합성 영수증 평가의 양식·촬영 조건 확대(기획서 목표: 핵심 필드 90%, 최대 100장)
3. **화면**: ⓘ 도움말을 화면별 주제로, 검수 상세(진행 표시·단축키·검토 포인트↔칸 강조·승인 되돌리기), 빠른 검색 `Alt+S`
4. **다듬기**: 사업자번호 체크섬, 오래된 영수증 경고, 다른 직원과의 같은 승인번호(인덱스 필요)
5. **발표 준비**: 최종 배포(`SCALING=1`)로 확장 시연 — 여러 장 올려 ocr-worker·노드가 늘어나는 것 보여 주기

범위 밖(기획서 Should/Could, 하지 않음): 알림, 기관별 지출 기준 설정, 사진 위 결과 표시, Athena 분석.

## 8. 꼭 알아야 할 결정과 함정

- **카드 영수증만** (현금·계좌이체·취소/반품 제외). 지출 분류 10개 고정. 카드번호는 찍힌 그대로.
- **프로필은 Cognito**, 관리자만 바꿈. 증빙에는 작성 당시 프로필을 복사해 둠(나중에 부서를 옮겨도 그대로).
- **AI는 제출·승인하지 않음.** 사용자가 말하지 않은 값을 넣지 않음. 서버가 AI 답을 검사해 영어·생각 노출·"바꿨다"는 거짓말을 다시 쓰게 함 ([ai.md](ai.md)).
- **공유 AWS**: 로컬 OCR 워커도 공용 큐의 모든 팀원 사진을 처리합니다. 실행 조건과 수정 절차는 [worker.md](worker.md).
- **Cost Explorer는 조직 정책(SCP)으로 막혀 있음** → 비용은 AWS Budgets로만 봄. 계정에는 팀이 쓰기 전 금액이 있어 프로젝트 예산은 **2026-10-01부터** 셈 ([aws.md](aws.md#비용)).
- **EKS·ALB는 시간당 과금** → 켠 날 지움. Terraform "No changes"는 비용이 없다는 뜻이 아님.
- Windows에서 배포할 때 생기는 문제(ECR 로그인, ALB 웹훅 인증서)는 `deploy.sh`가 처리 ([aws.md](aws.md#문제-해결)).

## 9. 용어

| 용어 | 뜻 |
|---|---|
| 증빙 | 영수증 한 장과 그 정보(칸·목적·분류·대화·이력)를 묶은 단위. 코드에서는 `receipt` |
| 분석 | 보정된 사진을 ocr-worker가 Bedrock으로 읽어 칸을 채우는 단계 (`analysis_status`) |
| 결과 확인 | 직원이 AI가 읽은 값이 맞다고 누른 것 (`result_confirmed_at`) |
| 제출 · 승인 · 보완 요청 | 검수 상태 (`review_status`: `submitted` · `approved` · `changes_requested`). 제출·승인은 항상 사람이 버튼으로 함 |
| 점검 (`checks`) | 저장할 때 서버가 계산하는 경고·오류 (검산·중복·심야·주말 등) |
| 검토 포인트 (`review_points`) | 검수자가 먼저 볼 것을 서버가 규칙으로 뽑은 목록. `code`·`fields`로 보완 요청과 연결 |
| 공용 큐 · 워커 | S3 `incoming/` 저장 → SQS 분석 큐 → ocr-worker. 팀이 하나를 같이 쓰며 누구의 워커든 누구의 사진이든 처리 |
| 개발자 모드 · `dev-*` 계정 | 로컬 전용 테스트 계정 10개(코드에 고정). 데이터는 공용 테이블에 `owner_sub=dev-…`로 저장 |
| 시드 데이터 | `seed_dev_data.py`가 넣는 개발 계정용 가짜 증빙 (`seed` 표시, 워커가 분석하지 않음) |
